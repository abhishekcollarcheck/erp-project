# Attendance Abbreviation Logic — Reference

Shift used throughout the examples below: **Start 10:00 AM, End 7:00 PM, Grace 15 min,
Half-shift 2:30 PM, Duration 9h**. All thresholds scale automatically to whatever
shift you pass in — nothing below is hardcoded to 9 hours in the code, this file
just uses 9h for concrete examples.

Legend: `In` = check-in time, `Out` = check-out time, `Start`/`End` = shift
start/end, `Grace` = grace window in minutes, `Half` = half-shift time,
`Late` = minutes the employee checked in after `Start` (0 if on time).

---

## 1. Core attendance (punch-only, no leave)

### P — PRESENT (Row 4)
Full day present. Matches **any** of:
1. `In <= Start` and `Out >= End` (on-time in, stayed till close).
2. `In` inside grace window (`Start < In <= Start+Grace`) **and** `Out >= End + Late`
   — i.e. if you used the grace window, you must make up the late minutes at
   checkout. *(This is your explicit rule: in at 10:07 → out must be ≥ 19:07.)*
3. Fallback: total hours worked (`Out - In`) ≥ full shift duration, regardless
   of clock alignment.

### A — ABSENT (Row 5)
Fallthrough: none of P / P:A / A:P matched. Typically: checked in late and left
before making up the shortfall, or worked well under half a shift.

### P:A — FIRST_HALF_PRESENT (Row 6)
Present for the first half only, left before the second half. Matches:
1. `In <= Start` and `Half <= Out < End`.
2. `In` inside grace window and `Out >= Half + Late` and `Out < End`.
3. Duration fallback: `In` within grace window, `Out < End`, and hours worked
   ≥ `(Half − Start)`.

### A:P — SECOND_HALF_PRESENT (Row 7)
Absent the first half, present for the second. Matches:
1. `In <= Half` and `In > Start + Grace` and `Out >= End + Late`.
2. Duration fallback: `In > Start + Grace` and hours worked ≥ `(End − Half)`.

### P:MP — PRESENT_MISS_PUNCH (Row 2) / MP:P — MISS_PUNCH_PRESENT (Row 3)
Exactly one punch recorded.
- Check-in exists, check-out missing → `P:MP`.
- Check-out exists, check-in missing → `MP:P`.

## 2. Week off / holiday

### WO — WEEK_OFF (Row 8) / HO — HOLIDAY (Row 9)
No punches at all on a scheduled week-off / holiday day.

### MP:POW, MP:POH, P:MPOW, P:MPOH (Rows 10–13)
Same "single punch missing" idea as P:MP / MP:P, but tagged for a week-off or
holiday: `MP:POW`/`MP:POH` = check-in missing; `P:MPOW`/`P:MPOH` = check-out missing.

### POW / POH — PRESENT_ON_WEEK_OFF / _HOLIDAY (Rows 14–15)
Employee voluntarily worked a full day on an off day: hours worked ≥ full
shift duration (9h in the example). **Not** evaluated against shift-start
lateness — nobody is "late" on a day they weren't scheduled to work.

### AOW / AOH — ABSENT_ON_WEEK_OFF / _HOLIDAY (Rows 16–17)
Punched in but worked less than half a shift's duration (< 4.5h).

### P:AOW / P:AOH — FIRST_HALF_PRESENT_WEEK_OFF / _HOLIDAY (Rows 18–19)
Worked between half and full duration, and arrived before the half-shift mark.

### A:POW / A:POH — SECOND_HALF_PRESENT_WEEK_OFF / _HOLIDAY (Rows 20–21)
Worked between half and full duration, and arrived at/after the half-shift mark.

## 3. Short leave (SL) — "buys back" 30 or 60 minutes

Short leave only applies with an **approved** short-leave request for that day.
It is checked *before* base attendance is computed, since it directly encodes
a present-with-adjustment pattern.

### SL(h):P — SHORT_LEAVE_HALF_PRESENT (Row 22) — 30-min leave, late arrival
`In` between `(Start+Grace)` and `(Start+30min)`, and `Out >= End`.

### P:SL(h) — PRESENT_SHORT_LEAVE_HALF (Row 23) — 30-min leave, early departure
- On-time: `In <= Start`, `Out` between `(End−30min)` and `End`.
- Grace: `In` inside grace window, `Out` between `(End−30min)+Late` and `End+Late`.

### SL(f):P — SHORT_LEAVE_FULL_PRESENT (Row 24) — 60-min leave, late arrival
`In` between `(Start+Grace)` and `(Start+60min)`, and `Out >= End`.

### P:SL(f) — PRESENT_SHORT_LEAVE_FULL (Row 25) — 60-min leave, early departure
- On-time: `In <= Start`, `Out` between `(End−60min)` and `End`.
- Grace: `In` inside grace window, `Out` between `(End−60min)+Late` and `End+Late`.

**Resolution note:** short-leave *duration* (30 vs 60 min) isn't a dedicated
column on `LeaveRequest` today. `leave-resolver.service.ts` derives it from
the existing `from_time`/`to_time` fields (≤30 min → half, otherwise → full).
If you add a dedicated duration field later, swap that in instead.

## 4. Casual / Earned leave (CL / EL) conversions

These require an **approved** `LeaveRequest` whose type resolves to `CL` or
`EL`, plus enough remaining balance (`allocated + carried_forward − used − pending`).

**Important:** the half-day conversions (CL:P / EL:P / P:CL / P:EL) only fire
if the *punch-only* base status already shows the matching half present — a
leave request can excuse an absence, it cannot invent a punch that never
happened.

### CL:P — CASUAL_LEAVE_PRESENT (Row 26) / EL:P — EARNED_LEAVE_PRESENT (Row 27)
Requires: base attendance = **A:P** (second half present), leave applied for
the **first half**, balance ≥ 0.5 day.

### P:CL — PRESENT_CASUAL_LEAVE (Row 28) / P:EL — PRESENT_EARNED_LEAVE (Row 29)
Requires: base attendance = **P:A** (first half present), leave applied for
the **second half**, balance ≥ 0.5 day.

### CL(A) — CASUAL_LEAVE_ABSENT (Row 30) / EL(A) — EARNED_LEAVE_ABSENT (Row 31)
Requires: base attendance = **A** (fully absent, no useful punches), and
either:
- a full-day CL/EL was requested but only 0.5–0.99 days of balance remain
  (auto-downgraded to a half-day deduction), **or**
- the employee explicitly requested only a first/second-half CL/EL for a day
  they were fully absent, with ≥ 0.5 day balance available.

### CL — CASUAL_LEAVE (Row 32) / EL — EARNED_LEAVE (Row 33)
Requires: base attendance = **A**, full-day CL/EL requested, and balance ≥ 1 day.

If balance < 0.5 day, the leave cannot be granted at all — the day remains **A**.

## 5. Evaluation order (why it matters)

```
1. Both punches missing        -> WO / HO / A
2. One punch missing           -> P:MP / MP:P (+ week-off/holiday variants)
3. Week-off or holiday         -> duration-based off-day evaluation (§2), done
4. Short-leave override        -> SL(h):P / P:SL(h) / SL(f):P / P:SL(f), if it matches
5. Base attendance from punches -> P / P:A / A:P / A   (§1)
6. CL/EL conversion over the base status                (§4)
7. Otherwise return the base status from step 5
```

Short leave is checked *before* base attendance because it's really a
specialised "present, with an approved adjustment" pattern. CL/EL is checked
*after*, because it needs to know the raw base status to decide whether a
half-day conversion is legitimate.

## 6. Files

- `attendance-rules.engine.ts` — pure rules engine (no DB access). Takes a
  punch row, a `Shift`, and an `AttendanceEvaluationOptions` object
  (`graceMinutes`, `isWeekOff`, `isHoliday`, `appliedLeave`, `availableLeaveDays`).
- `leave-resolver.service.ts` — bridges `LeaveRequest` / `EmployeeLeaveBalance`
  / `LeaveType` Sequelize models into the shape the engine expects, and
  reports leave usage (e.g. "how much CL has this employee used").

### Minimal usage example

```ts
import { evaluateAttendanceStatus } from './attendance-rules.engine';
import { resolveLeaveContextForDate } from './leave-resolver.service';

const { appliedLeave, availableLeaveDays } = resolveLeaveContextForDate(
  row.date,
  employeeLeaveRequests,   // LeaveRequest[] for this employee
  leaveTypesById,          // Map<number, LeaveType>
  employeeLeaveBalances,   // EmployeeLeaveBalance[] for this employee/year
);

const result = evaluateAttendanceStatus(row, shift, {
  graceMinutes: 15,
  isWeekOff,
  isHoliday,
  appliedLeave,
  availableLeaveDays,
});
// result.status, result.matchedRule, result.lateMinutes
```

## 7. Assumptions flagged for your review

The source sheet had a few cells that were ambiguous or garbled by OCR/merge
artifacts. Here's exactly what was assumed, so you can correct it if wrong:

- **A:P duration fallback (Row 7, Logic 4):** the sheet's formula
  `(Shift Duration − Shift End)` isn't dimensionally valid (mixes a duration
  with a clock time). Implemented as `(End − Half)` — the natural "second
  half's worth of hours" — matching the symmetric formula already used for
  P:A (`Half − Start`).
- **`half_shift_time`:** not yet a column on the `Shift` model in the code you
  shared. The engine auto-derives it as `Start + Duration/2` when absent, so
  it still works, but if `half_shift_time` should be independently
  configurable (not always the exact midpoint), add the column and it'll be
  picked up automatically (`(shift as any).half_shift_time` — worth typing
  properly on the model rather than casting).
- **Short-leave duration:** derived from `from_time`/`to_time` on
  `LeaveRequest` (see §3) since there's no dedicated minutes field.
- **CL(A)/EL(A) "apply first or second half":** interpreted as the case where
  the employee explicitly requested a half-day CL/EL on a day they were fully
  absent (rather than a full-day request downgraded by low balance) — see §4.
